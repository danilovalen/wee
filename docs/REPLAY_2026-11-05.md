Owner (register 758): *"I'd like to, after a solution is completed (sandbox, campaign, test, myself) to
replay it step by step, go back, go forward, to analyse it."*

Diagnosis only, nothing changed.

## What exists today

| Piece | Where | What it holds | What it does now |
|---|---|---|---|
| The run's start | `S.played` (`app/play.js:112`) | the room exactly as play began | used by the bug report |
| Every key pressed | `S.keylog` (`play.js:57`) | `{ t: tick, k: key }` per press, in order | used by the bug report (`play.js:178`) |
| A snapshot per move | `S.undoPlay` (`play.js:56`) | the whole game state after each counted move | Undo and Z; popped as you undo, so lost |
| Show solution | `S.demo`, `S.demoRunning` (`campaign.js:131`) | the solver's keys | plays them live, once, at play speed; cannot pause or step |
| A failed goal's path | `S.trail` (`goalCard.js:151`) | the tiles of one shortest path | drawn as a line, not played |
| The win card | `#win` (`index.html:150`) | "Play again", "Edit" | no way to look back at the run |

So **the data for a replay is already recorded for every run played by hand**: the start room and the
keys. The rules are deterministic (the same keys on the same room always give the same game; the solver
and the goals rely on this through `replayPath`). Show solution and Run produce key lists too. What is
missing is a way to look at it: nothing can pause, step or go back, and the win card ends the run.

Four sources, one shape:

| Who solved it | Where the moves come from |
|---|---|
| You, by hand (Sandbox test, Campaign, Puzzles) | `S.played` + `S.keylog` |
| Show solution (the solver) | the solver's move list (`S.demo`) |
| Run (campaign robot) | the robot's move list |
| A failed goal row (F1) | its shortest path |

## The proposal: a Replay view

**Opening it.** The win card gains **Replay**. Show solution and a failed goal row open the same view
instead of playing at full speed once.

**What it is.** The room as it was at the start, with a strip under it:

```
 |◀   ◀   ▶   ▶|      Move 7 of 19      ▶ Play
 ●──●──●──●──●──●──◉──○──○──○──○──○──○──○──○──○──○──○──○
```

- **◀ ▶** step back and forward **one move** (one slide from rest to rest, not one tick). Each step animates
  the slide at play speed, so you see what happened, and stepping back plays it in reverse.
- **|◀ ▶|** jump to the start and the end.
- **The strip** shows every move as a mark; tap one to jump there. Marks are tinted where something
  happened (a box pushed, a door changed, a berry eaten), so the interesting moves are easy to find.
- **▶ Play** runs it at play speed, and pauses on any tap.
- **Move 7 of 19** names where you are; the detail line says what that move did ("Slid right, pushed the
  box into the door").
- **Lenses stay on.** The solution line, the dots (750) and the What if lens (755) draw for the position
  on screen, so analysing a position is the same as analysing a room.
- **Controller and keyboard:** shoulders or ← → step, Home/End jump, A plays or pauses, B leaves (740). No
  hover needed.

**Leaving it.** "Back" returns to where you came from. In the Sandbox, a fourth button, **Edit from here**,
takes the position on screen into the editor as a new room, which turns any point of a run into a
starting point for a puzzle.

**How stepping works.** Moves, not ticks, are the steps: the keys are replayed once at open to record a
snapshot of the whole game after each move (the same snapshot Undo already takes). Stepping then just shows
a stored snapshot, so going back is instant and exact, even through doors, deaths and respawns. A 100-move
run is 100 snapshots of a small room, which is cheap.

## Smaller things it settles

- **Show solution today plays once and is gone.** In the Replay view it can be stepped and re-watched.
- **757 (Undo on the stuck banner):** Replay is not Undo. Undo still changes the run you are playing;
  Replay only looks.
- **A run that did not win** (you stopped, or got stuck) could be replayed too, from the pause menu. Worth
  deciding.
